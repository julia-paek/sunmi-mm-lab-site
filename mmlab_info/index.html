독일 시스템창호

KBE와 KÖMMERLING을 별도 기본 제품으로 나누지 않습니다. 공통 profine 시스템과 개폐 방식을 먼저 설명하고, KBE OnLevel과 KÖMMERLING Add-On을 선택 옵션으로 구분합니다.

KCC 창호

PC에서는 세 개 태그 옆에 작은 YouTube 광고 썸네일을 배치합니다. 모바일은 기존 세로 흐름을 유지하고 문구는 반드시 ‘KCC 광고’로 씁니다.

고려안전방충망

제품 3개의 전체 모서리가 보여야 합니다. 확대 크롭을 피하고 투명 배경 v2 이미지를 contain 방식으로 사용합니다.

LX · PL

LX 히어로 클릭 선택 표시는 제거했고 자동 장면 전환은 유지합니다. PL 상단 중복 탭은 없애고 카드 선택 후 AL 방식의 모달로 상세를 엽니다.

LX하우시스는 가장 많이 사용하는 주력 브랜드입니다.

사용 빈도가 높은 만큼 제품군과 모델, 소재, 개폐 방식, 유리와 마감 옵션이 많아 전체 구조가 가장 복잡합니다. 모델 번호를 먼저 나열하면 고객이 선택하기 어렵기 때문에 큰 분류부터 단계적으로 안내합니다.

  • 1차 분류: 뷰프레임 일반창 / 유로시스템9 시스템창
  • 뷰프레임: 완성창 / 제작창
  • 유로시스템9: PL(PVC) / AL(알루미늄)
  • 공간 분류: 발코니창 / 실내창 / 분합문 / 도어 / 여닫이창
  • 성능·사양: 단창·이중창, 유리 두께, 단열·차음
  • 선택 옵션: 핸들, 내부 컬러 시트, 외부 ASA, 개폐 방식
  • 설명 순서: 공간과 용도 → 제품군 → 모델 → 세부 옵션
  • 중복 탭과 모델 선택 표시를 겹쳐 사용하지 않음
05 · why MM LAB

창호 전문성과 인테리어를
필요한 만큼 연결합니다.

MM LAB이 직접 책임지는 창호 시공과, 별도 전문회사가 담당하는 인테리어를 명확히 나누면서 한 프로젝트로 연결하는 것이 가장 중요한 사업 구조입니다.

정품 창호는 MM LAB이 직접.WINDOW DIRECT · INTERIOR PARTNER NETWORK

MM LAB은 정품 창호를 직접 상담·공급·시공합니다. 인테리어는 MM LAB이 직접 시공하지 않으며, 10년간의 현장 경험을 통해 실력과 신뢰도를 검증한 별도 파트너 업체만 선별해 연결합니다. 고객은 창호만 단독으로 맡기거나, 전체 인테리어가 필요할 때 창호와 인테리어를 함께 진행할 수 있습니다.

01 · WINDOW ONLY

창호 단독 시공

MM LAB이 창호 전체를 직접 담당합니다.
제품 상담부터 정품 공급, 실측, 시공과 창호 범위의 사후 대응까지 한 흐름으로 진행합니다.

02 · FULL INTERIOR

창호 + 전체 인테리어

창호는 MM LAB, 인테리어는 검증된 파트너가 담당합니다.
두 영역을 연결해 전체 일정을 조율하되, 인테리어 계약·시공·책임과 사후 대응은 해당 파트너 업체가 별도로 맡습니다.

20–30%POTENTIAL COST SAVING

High Quality, Low Price

창호는 전체 인테리어 비용에서 비중이 크고, 경우에 따라 주방 한 곳을 바꿀 수 있을 만큼 큰 예산이 들어갑니다. MM LAB은 창호 전문 유통·시공 구조로 불필요한 유통 단계를 줄여 정품만 사용하면서도, 동일·유사 사양의 통합 견적과 비교할 때 최대 20~30%까지 비용을 낮출 수 있는 구조를 지향합니다. 창호 품질은 높게 유지하고 전체 인테리어 예산은 효율적으로 배분할 수 있다는 점이 MM LAB만의 핵심 경쟁력입니다.

※ 20~30%는 모든 현장에 동일하게 보장되는 할인율이 아닙니다. 제품 사양, 수량, 철거·보양, 현장 조건과 비교 견적의 포함 범위에 따라 달라지므로 최종 견적으로 확인합니다.

완전하게 복원합니다.

단순 소스 폴더도 제공하지만 실제 협업은 Git 이력을 복원해 진행하는 것이 안전합니다.

CLONE
git clone "02_Git_작업이력/sunmi-mm-lab-site-all-branches.bundle" sunmi-mm-lab-site
WORK BRANCH
git switch site-structure
REMOTE
git remote set-url origin https://github.com/julia-paek/sunmi-mm-lab-site.git
FLOW
Pull → 작업 → 검사 → Commit → Push → 검토 → main 배포

외부 작업자는 본인 Fork와 별도 브랜치를 사용하고 Pull Request로 전달하는 방식을 권장합니다.
