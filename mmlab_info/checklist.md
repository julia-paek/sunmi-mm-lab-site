### LX와 PL 페이지

- LX하우시스는 MM LAB에서 가장 많이 사용하는 주력 브랜드입니다.
- 사용 빈도가 높은 만큼 뷰프레임과 유로시스템9, 완성창과 제작창, PL과 AL, 단창과 이중창, 개폐 방식, 유리, 핸들, 컬러 시트와 외부 마감까지 선택 요소가 많아 구조가 가장 복잡합니다.
- 고객에게 모델 번호부터 보여주지 않고 `공간·용도 → 일반창/시스템창 → 제품군 → 모델 → 옵션` 순서로 안내합니다.
- 뷰프레임 일반창은 완성창과 제작창으로, 유로시스템9 시스템창은 PL(PVC)과 AL(알루미늄)로 구분합니다.
- 완성창은 발코니 단창·이중창과 일반형·고급형·베젤리스 모델을 포함합니다.
- 제작창은 실내창, 분합문, 여닫이 도어, 측면·상부 여닫이창 등 공간별 제품을 포함합니다.
- 모델별 유리 두께, 적용 공간, 핸들, 내부 컬러 시트, 외부 ASA와 선택 가능 사양이 다를 수 있으므로 최종 견적 전에 다시 확인합니다.
- LX 히어로는 자동 장면 전환은 유지하고 클릭 시 모델 선택 표시가 나오지 않게 정리했습니다.
- PL 페이지의 상단 중복 탭은 제거했습니다.
- PL 상세 내용은 AL 페이지와 같은 방식으로 카드 선택 후 모달에서 표시합니다.

## MM LAB의 핵심 사업 구조

MM LAB의 가장 중요한 차별점은 창호 전문 시공과 인테리어 파트너를 한 프로젝트 안에서 연결하되, 각 회사의 역할과 책임을 분명하게 나누는 것입니다.

### 고객이 선택할 수 있는 두 가지 방식

1. **창호 단독 시공**
   - MM LAB이 제품 상담, 정품 창호 공급, 실측, 시공과 창호 범위의 사후 대응을 직접 담당합니다.
2. **창호 + 전체 인테리어**
   - 창호는 MM LAB이 직접 담당합니다.
   - 인테리어는 MM LAB이 직접 시공하지 않습니다.
   - 10년간의 현장 경험을 통해 실력과 신뢰도를 검증한 파트너 업체만 선별해 연결합니다.
   - 인테리어 계약·시공·책임과 사후 대응은 연결된 파트너 업체가 별도로 담당합니다.

### High Quality, Low Price가 가능한 이유

- 창호는 전체 인테리어 예산에서 비중이 큰 항목이며, 경우에 따라 주방 한 곳을 교체할 수 있을 만큼 큰 비용이 들어갑니다.
- MM LAB은 창호 전문 유통·시공 구조로 불필요한 유통 단계를 줄입니다.
- 정품 창호만 사용하면서도 동일·유사 사양의 통합 견적과 비교할 때 최대 20~30%까지 비용을 낮출 수 있는 구조를 지향합니다.
- 절감한 창호 비용을 다른 인테리어 항목에 효율적으로 배분하면서 전체 품질을 높일 수 있다는 것이 핵심 경쟁력입니다.

`20~30%`는 모든 현장에 동일하게 보장되는 할인율로 표현하지 않습니다. 제품 사양, 수량, 철거·보양, 현장 조건과 비교 견적의 포함 범위에 따라 달라지므로 최종 견적으로 확인한다는 안내를 함께 둡니다.

## 추가 개발 필수

### 시공사진 관리 어드민

- 창호 시공사진과 인테리어 시공사진을 별도 분류로 관리
- 사진 업로드, 교체, 삭제, 순서 변경
- 제목, 현장 설명, 지역, 공사 유형, 대체텍스트 입력
- 임시저장, 공개, 비공개 상태 관리
- PC·태블릿·아이폰용 반응형 이미지 생성
- 이미지 용량 최적화와 WebP 등 웹 형식 변환
- 삭제 전 확인과 복구 가능한 보관 방식
- 관리자 로그인과 권한 검증

GitHub Pages는 정적 화면만 공개할 수 있으므로 안전한 어드민을 구현하려면 별도의 관리자 인증, 이미지 저장소와 데이터베이스가 필요합니다. HTML·JavaScript 비밀번호 화면만으로 관리자 기능을 보호하지 않습니다.

### 오픈카카오톡 상담 연결

- 홈페이지의 상담신청 버튼에서 MM LAB 오픈카카오톡으로 연결
- PC에서는 새 탭, 모바일에서는 카카오톡 앱 연결을 우선
- 연결 실패 시 URL 복사 또는 재시도 안내 제공
- 오픈카톡 주소를 코드 수정 없이 관리 화면에서 변경 가능하게 구성
- 버튼이 위치한 페이지와 제품 정보가 상담 과정에서 구분되도록 설계

### 완료 확인

- 관리자 사진 등록 후 창호·인테리어 시공사례 화면에 정상 반영
- 공개·비공개, 순서 변경과 삭제 복구 확인
- 모바일·태블릿·PC에서 이미지 비율과 로딩 속도 확인
- 상담신청 버튼이 PC와 모바일에서 올바른 오픈카톡으로 연결
- 관리자 페이지가 로그인하지 않은 사용자에게 노출되지 않음

## 화면 검수 체크리스트

### PC 1440px 이상

- 히어로 제목과 버튼이 이미지 핵심을 가리지 않는가
- KCC 동영상 카드가 태그 3개 옆에 작게 배치되는가
- 독일 시스템창호 두 개폐 방식 이미지가 전부 보이는가
- KBE 유리난간대와 KÖMMERLING 블라인드가 같은 선택 단계로 이해되는가

### 태블릿 768~1024px

- 2열 영역이 너무 좁아지면 자연스럽게 1열로 바뀌는가
- 본문과 이미지 사이 선이 겹치지 않는가
- 표가 화면 밖으로 잘리지 않는가

### 아이폰 375~430px

- 가로 스크롤이 생기지 않는가
- 제품 이미지의 좌우·상하 모서리가 잘리지 않는가
- 버튼과 링크의 터치 영역이 충분한가
- 제목의 한글 단어가 어색하게 한 글자씩 끊기지 않는가
- KCC 모바일 구성은 기존 세로 흐름을 유지하는가

### 기능과 경로

- 공통 메뉴와 상담 모달이 작동하는가
- YouTube 링크가 새 탭으로 열리는가
- 이미지·영상·CSS·JS 경로가 404가 아닌가
- 브라우저 콘솔에 JavaScript 오류가 없는가
- 키보드 포커스가 보이는가
- `prefers-reduced-motion` 설정을 방해하지 않는가

## 배포 전 체크리스트

- `git status`로 예상하지 않은 파일이 섞이지 않았는지 확인
- `git diff --check` 통과
- PC·태블릿·아이폰 화면 확인
- `site-structure` 또는 별도 브랜치에 커밋·푸시
- 사용자 검토와 배포 승인을 받은 뒤 `main` 반영
- GitHub Pages 상태가 `built`가 된 뒤 실제 URL HTTP 200과 핵심 문구 확인
- CNAME·DNS·Pages 설정은 변경하지 않음
