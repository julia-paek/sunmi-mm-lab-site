# MM LAB 홈페이지 작업 인수인계

작성 시점: 2026-08-03 09:58 KST  
라이브 사이트: https://sunmi.works/  
GitHub 저장소: https://github.com/julia-paek/sunmi-mm-lab-site  

## 1. 이 ZIP의 목적

현재 MM LAB 홈페이지를 다른 작업자가 그대로 이어서 수정하고 확장할 수 있도록 만든 완전한 인수인계 패키지입니다.

- 현재 사이트 전체 소스
- 전체 Git 작업 이력 복원용 bundle
- 독일 시스템창호 작업에 사용한 카탈로그 원본
- 최근 수정 요청 참고 이미지
- 현재 작업 현황과 검수 기준

현재 소스는 GitHub에 커밋·푸시되어 있으며 공개 사이트에도 배포된 상태입니다.

## 추가 개발 예정

- 창호 시공사진과 인테리어 시공사진을 관리자가 직접 업데이트하는 어드민
- 상담신청 버튼에서 MM LAB 오픈카카오톡으로 연결되는 기능

세부 개발 범위와 검수 조건은 `00_MM-LAB_작업설명서.html`의 **추가 개발** 섹션과 `05_작업현황_및_검수체크리스트.md`를 확인합니다.

## 4. 바로 화면만 확인하는 방법

`01_사이트_전체소스/index.html`을 브라우저로 열면 됩니다.

인수인계 내용부터 확인하려면 루트의 `00_MM-LAB_작업설명서.html`을 먼저 엽니다.

주요 확인 페이지:

- 홈: `01_사이트_전체소스/index.html`
- KCC 창호: `01_사이트_전체소스/windows/kcc/index.html`
- 독일 시스템창호: `01_사이트_전체소스/windows/kbe/index.html`
- 고려안전방충망: `01_사이트_전체소스/screens/kogo/index.html`
- LX 창호: `01_사이트_전체소스/windows/lx/index.html`

일부 공통 메뉴와 동작은 로컬 서버에서 확인하는 것이 더 정확합니다.

## 5. Git 이력까지 복원하는 방법

터미널에서 이 ZIP을 푼 폴더로 이동한 뒤 아래처럼 복원합니다.

```bash
git clone "02_Git_작업이력/sunmi-mm-lab-site-all-branches.bundle" sunmi-mm-lab-site
cd sunmi-mm-lab-site
git switch site-structure
git remote set-url origin https://github.com/julia-paek/sunmi-mm-lab-site.git
git status
```

GitHub 쓰기 권한이 없는 외부 작업자는 원본 저장소를 Fork한 뒤 별도 브랜치에서 작업하고 Pull Request로 전달하는 방식을 권장합니다.

## 6. 반드시 지켜야 할 사이트 규칙

상세 규칙은 `01_사이트_전체소스/AGENTS.md`와 `01_사이트_전체소스/ROUTES.md`를 먼저 읽습니다.

- 정식 페이지 주소는 `폴더/index.html` 구조를 사용합니다.
- 주소 폴더명은 영문 소문자와 하이픈을 사용합니다.
- 모든 정식 페이지는 루트 `sitenav.js`를 연결합니다.
- 창호·방충망 페이지는 `common.js`도 연결합니다.
- 새 페이지에 과거 파일인 `gnb.js`를 사용하지 않습니다.
- 상대 이미지·CSS·JS 경로는 페이지 깊이에 맞게 확인합니다.
- PC·태블릿·아이폰 화면, 이미지 잘림, 가로 스크롤, 메뉴 링크, 콘솔 오류를 확인합니다.
- 사용자 승인 없이 `main`, `CNAME`, `.nojekyll`, Pages 설정, 도메인, DNS를 변경하지 않습니다.
- 작업 중에는 `site-structure` 또는 별도 작업 브랜치를 사용합니다.

## 7. 외부 작업 결과를 다시 받을 때

받아온 ZIP이나 폴더를 현재 Git 저장소 위에 덮어쓰지 않습니다.

1. 별도 폴더에 압축 해제
2. 현재 소스와 차이 비교
3. 필요한 파일만 선택 반영
4. PC·모바일·경로·콘솔 검사
5. 작업 브랜치에 커밋·푸시
6. 검토 후 공개 배포

## 8. 공개 배포 정보

- GitHub Pages는 `main` 브랜치 루트를 공개합니다.
- 사용자 도메인은 `sunmi.works`입니다.
- 현재 HTTPS가 적용되어 있습니다.
- CNAME과 DNS는 정상 작동 중이므로 임의 수정하지 않습니다.

일반 작업 흐름은 `Pull → 작업 → 검사 → Commit → Push → 검토 → main 배포`입니다.
